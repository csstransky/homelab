MOTHERLODE · Checkpoint 8 · running and tested 2026-10-06

Your own Google Drive, on your own disks

Nextcloud gives the NAS a web page, a phone app, share links, Office editing and search, reachable from anywhere at motherlode.tailb6c0f2.ts.net. It shows the same folders Windows sees through Samba. There is one copy of every file and two ways in.

How a request gets in

From your phone to your Photos folder

Tailscale Funnel is the only door from the internet. It holds the HTTPS certificate and hands traffic to Nextcloud, which listens only on MOTHERLODE itself. At home, Windows goes straight to the same folders through Samba.

Five locks on the front door

1 · HTTPS

Encrypted end to end

Funnel's certificate for *.ts.net. Nobody on the café Wi-Fi can read the traffic.

2 · Password

Changed from the generated one

The AIO-generated password was visible in a screenshot, so it was replaced.

3 · Two-factor

Required for every account

twofactorauth:enforce --on. A 6-digit code from Duo Mobile, plus backup codes kept out of git.

4 · Brute force

Throttled per visitor IP

Repeated failures slow that IP down. It sees the real IP, not the proxy, so an attacker can't lock you out.

5 · Audit log

Every login, with its IP

Your phone showed up as 166.198.25.32 and 2600:387:f:5f33::8, your carrier's addresses. Read it with nc-logins.

One copy of every file

Two doors into the same folders

AIO lets Nextcloud see exactly one host folder. /srv/nas is that folder: each share is bind-mounted into it, which shows the same files at a second path without copying anything. Nextcloud attaches each one with External Storage.

Permissions: both sides can write

Samba writes as you (group nas); Nextcloud writes as www-data. Each share carries these ACL entries, and the default: ones are inherited by every new file and folder.

user:www-data:rwx
Nextcloud can read and change what's already there.
group:nas:rwx
You, over Samba, can too.
default:user:www-data:rwx default:group:nas:rwx
New files inherit both. A phone upload stays editable from Windows, and a Windows file stays editable from the phone.

Applied to 115,294 existing entries. /media/ghost, where the desktop auto-mounts USB drives, is left out.

Off the SSD

Nothing important lives only on the boot drive

The OS SSD has no mirror and no snapshots. Nextcloud's database moved to ZFS, and the rest of what matters gets copied there every night, then on to tank500gb with everything else.

alwaysDocker volumes on ZFS

Database, AIO config, search index: /tank1tb/Apps/docker-volumes, mounted at /var/lib/docker/volumes. Docker refuses to start without it.

every hourApps snapshot

sanoid freezes the volumes, Postgres included, at one instant.

02:30ssd-backup

/etc, /root, /home/ghost (no caches) → /tank1tb/Backups/motherlode-ssd, root-only.

03:00nightly copy

Documents, Photos, Music, Apps, Nextcloud and now Backups → tank500gb.

Not copied, on purpose: Docker images, Debian packages and caches. They're all re-downloadable.

Getting a shell

SSH into MOTHERLODE

Anywhere · Tailscale on
ssh ghost@motherlode

Tailscale SSH: no password or key. It checks your GitHub login, and may send you to a browser for a quick re-check.

Phone · Termius
host  motherlode
user  ghost

Same thing from the phone, with the Tailscale app on.

At home · no Tailscale needed
ssh ghost@192.168.1.59

Regular OpenSSH on the LAN, with your Linux password. Works from ZEPHYR's PowerShell too.

SSH is never public: Funnel only forwards HTTPS on 443 to Nextcloud.

Later

Adding a new share

1 · folder

Create it (ZFS dataset or folder), group nas, mode 2775.

2 · Samba

Add a [Name] block to smb.conf, reload smbd.

3 · ACLs

Same two setfacl lines as the others.

4 · /srv/nas

One bind line in /etc/fstab, then mount.

5 · restart

AIO stop and start so the container sees it.

6 · attach

files_external:create + applicable + scan.

Exact commands: docs/services/nextcloud.md → "Adding a new share later".

What was run

The commands, in order

Prepare the folders host

zfs snapshot tank1tb/Photos@pre-nextcloud-acl-2 …
Safety snapshot before touching permissions on 100k files.
setfacl -R -m u:33:rwX,g:nas:rwX /tank1tb/Photos
find … -type d -exec setfacl -m d:u:33:rwx,d:g:nas:rwx …
Give Nextcloud access now, and make new files inherit it.
/tank1tb/Photos /srv/nas/Photos none bind,…   # /etc/fstab ×5
All five shares under one folder Nextcloud can be given.

Start Nextcloud host + you

docker compose up -d     # nextcloud/compose.yaml
Starts the AIO master container with the data dir, the /srv/nas mount and port 11000 bound to localhost.
tailscale funnel --bg 11000
Puts motherlode.tailb6c0f2.ts.net on the internet. You approved Funnel in the Tailscale console.
https://192.168.1.59:8080
You: saved the passphrase, entered the domain, chose Collabora + search + previews, started the containers.

Wire it up occ inside the container

occ app:enable files_external
occ files_external:create /Photos local null::null -c datadir=/srv/nas/Photos
Attach each share (×5), for user admin, sharing on, check for changes on access.
occ files:scan admin
Index what's already there: 106,364 entries, 0 errors.
occ twofactorauth:enforce --on
No login without the second factor.
curl -u probe-user:wrong-pass …/remote.php/dav/
One deliberate failed login, to prove brute-force protection sees real IPs.

Move Docker's data onto ZFS host

docker exec nextcloud-aio-mastercontainer /daily-backup.sh
systemctl stop docker
Clean stop: AIO dumps the database first.
rsync -aHAX --numeric-ids /var/lib/docker/volumes/ /tank1tb/Apps/docker-volumes/
Copy 42,396 entries, then checksum-verify.
/tank1tb/Apps/docker-volumes /var/lib/docker/volumes none bind,…
RequiresMountsFor=/var/lib/docker/volumes
Mount them back where Docker expects, and make Docker wait for ZFS.
