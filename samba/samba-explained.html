How Samba turns ZFS folders into Windows drives

Samba is a program on MOTHERLODE that speaks Windows' file-sharing language (SMB). Windows asks for \\MOTHERLODE\Documents; Samba checks who you are, looks up which Linux folder that name means, and reads or writes the file there. To Windows it looks like an ordinary drive.

Who gets in

Three locks, checked in order

Lock 1 · Samba password

Are you really ghost?

Samba keeps its own password list, separate from your Linux login. You set it with smbpasswd. Windows saves it once in Credential Manager.

fails → NT_STATUS_LOGON_FAILURE
Lock 2 · smb.conf rules

Is this user allowed here?

valid users = ghost on every share, guest ok = no, map to guest = Never. No anonymous access, and SMB1 (old, insecure) is switched off.

fails → NT_STATUS_ACCESS_DENIED
Lock 3 · Linux permissions

May ghost write this folder?

Share folders are root:nas mode 2775. ghost is in group nas, so it can write. The 2 (setgid) makes every new file inherit group nas.

fails → Access denied in Explorer
/etc/samba/smb.conf, line by line

The settings file

Copied word for word from the September design. One share shown; the other four are identical apart from name and path. The repo copy is samba/smb.conf.

[global]
Settings for the whole server.
workgroup = WORKGROUP
Old Windows grouping name. Mostly cosmetic with SMB2+; your PC uses DIAMOND_DOGS and that is fine.
server role = standalone server
A plain file server, not a Windows domain controller.
security = user map to guest = Never
Every connection must log in with a real user and password. Bad logins are refused, never turned into a guest.
server min protocol = SMB2
Refuse SMB1, the version WannaCry used. Windows 10/11 speak SMB3 anyway.
unix password sync = yes
Only applies to password changes made from Windows. Your sudo smbpasswd did not touch the Linux password (checked).
load printers = no disable spoolss = yes
No printer sharing.
[Documents]
The name Windows sees: \\MOTHERLODE\Documents.
path = /tank1tb/Documents
The Linux folder behind it.
read only = no guest ok = no valid users = ghost
Writable, no guests, only ghost.
force group = nas
Files are written with group nas, so a second user or Music Assistant can be added to nas later.
create mask = 0664 directory mask = 2775
New files rw-rw-r--, new folders rwxrwsr-x. The group can edit, others can only read.
How Windows finds MOTHERLODE

Three programs on MOTHERLODE

smbd

TCP 445 (and 139)

Does the actual file sharing. Everything above is smbd.

wsdd2

UDP 3702 · 5355

Announces MOTHERLODE so it shows under Network in Explorer, and answers "who is MOTHERLODE?" (LLMNR). Added this time; Windows 10/11 no longer use the old method.

nmbd

UDP 137 · 138

Old NetBIOS name service. Also answers name lookups, and is how MOTHERLODE asked your PC its name. Kept as in the old setup.

Set up

sudo groupadd -g 1001 nas
Create group nas with ID 1001. The folders on the ZFS disks were already stamped with 1001 from the old install, so they matched instantly.
sudo usermod -aG nas ghost
Add ghost to nas (-a = append, keep the other groups).
sudo apt-get install -y --no-install-recommends samba smbclient attr wsdd2
Install the server (samba), a test client (smbclient), file-attribute tools (attr) and Windows discovery (wsdd2). Services start automatically.
stat -c '%U:%G %a %n' /tank1tb/Documents /media /other …
Check owner, group and mode of each share folder. All already root:nas 2775; nothing to fix.
sudo cp -a /etc/samba/smb.conf /etc/samba/smb.conf.debian-default
Back up Debian's default config before replacing it.
sudo tee /etc/samba/smb.conf <<'EOF'
[global] … [Documents] … [Other]
EOF
Write the new config (the file explained above).
sudo testparm -s
Samba's spell-checker for smb.conf. Result: loaded OK, ROLE_STANDALONE.
sudo systemctl restart smbd nmbd
Restart the servers so they read the new config.
sudo ss -tlnp | grep -E ':(139|445) '
Confirm smbd is listening on the network ports.

Password you

sudo smbpasswd -a ghost
Add ghost to Samba's password list (-a = add). First try was blank.
sudo smbpasswd ghost
Change it to a real password.

Prove it works

sudo passwd -S ghost
Show when the Linux password last changed: 2026-09-28. So the Samba password did not leak into your login.
smbclient //localhost/Documents -U 'ghost%' \
  -c "put smbtest.txt; mkdir smbtestdir; get smbtest.txt smbtest.back"
Act like Windows: upload a file, make a folder, download it again. Run on all five shares.
cmp smbtest.txt smbtest.back
Byte-compare the round trip. Identical on every share.
stat -c '%U:%G %a %n' /tank1tb/Documents/smbtest*
Check the result: files ghost:nas 664, folders ghost:nas 2775.
smbclient //localhost/Documents -N -c ls
smbclient //localhost/Documents -U 'someone%' -c ls
Try anonymous (-N) and a made-up user. Both refused.
smbclient //192.168.1.59/Documents -U 'ghost%' -c ls
Same test over the real network address instead of localhost.
sudo rm -f …/smbtest.txt; sudo rmdir …/smbtestdir
Delete the test files from all five shares.
smbclient //localhost/Documents -U 'ghost%' -c ls
After your new password: a blank password is now refused (LOGON_FAILURE).
sudo pdbedit -L
List Samba's users: just ghost.
sudo ss -ulnp
Confirm the discovery programs are listening (137/138 nmbd, 3702/5355 wsdd2).
sudo smbstatus
Who is connected right now. Showed your PC with all five shares open.
nmblookup -A 192.168.1.64
Ask that PC its Windows name: ZEPHYR.

Words

Glossary

SMBWindows' file-sharing protocol. Samba is the Linux program that speaks it.
ShareA folder Samba publishes under a name, like Documents.
smb.confSamba's settings file: /etc/samba/smb.conf.
Group (nas)A set of Linux users that share permissions on the NAS folders.
2775 / setgidFolder mode: owner and group can write; new items inherit the folder's group.
MirrorTwo disks holding the same data; one can die without loss.
