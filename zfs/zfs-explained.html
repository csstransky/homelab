How six disks became three pools and a pile of folders

ZFS is the filesystem that holds the NAS data. It groups whole disks into pools, can keep two disks as exact copies of each other (a mirror), and checksums every block so it notices when a disk hands back bad data. Inside a pool you carve out datasets, which show up as ordinary folders.

The four ideas

Pool, mirror, dataset, checksum

Pool

A bucket made of disks

ZFS treats one or more disks as one storage space. You never format the disks yourself; the pool manages them. Each pool here is named after its size.

Mirror

Two disks, same data

Every write goes to both. If one disk dies, the other has everything and the pool shows DEGRADED instead of failing. You lose half the raw space.

Dataset

A folder with superpowers

tank1tb/Pictures looks like a folder at /tank1tb/Pictures, but it can have its own snapshots, compression and quotas. That is why each big category is its own dataset.

Checksum + scrub

ZFS notices bad data

Every block is stored with a fingerprint. A scrub reads everything and compares. On a mirror, a bad copy is repaired from the good one automatically.

How the pools were created (2026-09-27)

The settings, line by line

From zpool history. Every dataset inherits these from its pool.

zpool create tank1tb mirror …WD10EZEX…-part1 …TOSHIBA…-part1
Make a pool called tank1tb from two disks as a mirror, named by their permanent /dev/disk/by-id/ names.
-o ashift=12
Use 4 KB blocks, matching modern disks' physical sectors. Can never be changed later, so it matters.
-o cachefile=/etc/zfs/zpool.cache
Write the pool into the list Debian reads at boot to import pools automatically.
-O compression=lz4
Compress everything with a very fast method. Already-compressed files (photos, movies) pass through untouched; documents shrink.
-O xattr=sa -O acltype=posixacl
Store extra file attributes and Linux permission lists efficiently. Samba and Windows metadata use these.
-O dnodesize=auto
Lets those attributes fit inside the file's own record, so reading them costs no extra disk seek.
-O relatime=on
Update "last opened" times only occasionally, not on every read. Fewer pointless writes.
-O mountpoint=/tank1tb
Where the pool appears as a folder. Datasets appear underneath: /tank1tb/Pictures.
zfs create tank1tb/Documents (×6)
One dataset per category: Documents, Pictures, Music, Backups, Nextcloud, Apps.
Why the import needed -f

"The pool was last accessed by another system"

What ZFS saw

Each pool remembers the hostid of the computer that last used it. The pools were built on 09-27 by the old Debian install. Debian was then reinstalled, and the new install got a new hostid (017c5e3e).

Why ZFS stops you

Two computers writing to one pool at the same time would wreck it. So when the hostid does not match, ZFS refuses unless you say -f (force), meaning "I know no other computer is using these disks".

Why -f was safe here

The "other system" was this same machine before the reinstall. The disks are only connected to MOTHERLODE. After the import the pools carry the new hostid, so this happens only once.

What happens at every boot

From power-on to mounted folders

zfs-load-module

Loads the ZFS kernel module (built by DKMS for each kernel; needs Secure Boot off).

zfs-import-cache

Reads /etc/zfs/zpool.cache and imports the three pools listed there.

zfs-mount

Mounts every dataset at its mountpoint: /tank1tb/*, /tank500gb, /media.

/etc/fstab

Mounts /other by its UUID. The DVD drive's line points at /mnt/cdrom, outside /media.

zfs-zed

The ZFS event daemon. Watches for disk errors (alerts get wired up in Checkpoint 13).

smbd

Samba starts and shares the mounted folders.

All of these were already enabled by the Debian package. The reboot check (still pending) confirms this order works without anyone touching it.

Turn off "crash the machine if a task waits on disk for 2 minutes". A struggling disk or a long scrub could otherwise crash the NAS. The other crash-capture settings stay.

Import the pools

sudo zpool import -f -d /dev/disk/by-id \
  -o cachefile=/etc/zfs/zpool.cache tank1tb
Bring the pool online. -f: hostid mismatch (explained above). -d /dev/disk/by-id: use permanent disk names, never sda/sdb, which change between boots. cachefile: remember it for the next boot. Repeated for tank500gb and media.
sudo zpool status
zfs list
All three ONLINE, 0 read/write/checksum errors. All datasets mounted.
sudo zpool scrub tank1tb tank500gb media
Read and verify every stored block. 0 errors, in seconds, because the pools are nearly empty.
zfs get compression,xattr,acltype,…
zpool get ashift,autotrim …
sudo zpool history
Read back the settings and the full log of how each pool was created, for the docs.
find /tank1tb /tank500gb /media -maxdepth 2 -ls
What is on the pools: almost nothing. Owner group 1001 on the share folders, the old nas group ID, later reused for Samba.

Bring back /other

sudo blkid …WD6400AAKS…-part2
Confirm the partition: ext4, label other, UUID 5250af8d….
sudo e2fsck -fn …-part2
sudo dumpe2fs -h …-part2
Read-only check (-n changes nothing). Clean, except the old install had shut down without unmounting it, so its journal was waiting to be replayed.
sudo mkdir -p /other

Create the mount folder and add /other to the boot mount list, by UUID so it never depends on drive letters.
sudo systemctl daemon-reload
sudo mount /other
findmnt /other; dmesg | tail
Tell systemd about the fstab change, mount it, confirm. Kernel said recovery complete: the journal was replayed.

Glossary

by-idPermanent disk names from the model and serial number, in /dev/disk/by-id/. sda, sdb… change between boots.
Import / exportBringing a pool online on this machine, or cleanly handing it off.
hostidAn ID for this installation. Pools remember the last one that used them.
DEGRADEDA mirror with one disk missing or failed. Still works; replace the disk.
DKMSRebuilds the ZFS kernel module whenever Debian installs a new kernel.
fstab/etc/fstab: the list of non-ZFS filesystems to mount at boot.
ARCZFS's read cache in RAM.
ext4Debian's standard filesystem. No checksums or mirrors, but simple.
